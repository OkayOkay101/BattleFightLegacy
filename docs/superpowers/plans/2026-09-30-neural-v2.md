## Shared interfaces (binding contract)

- `server/training/NeuralSchema.js` exports `getSchema(version = 1)`. Schema properties: `version`, `observationCount`, `actionCount`, `maxOptions`, `actorDimensions`, `criticDimensions`, `schemaHash`. V1: 86/17/16/[103,64,64,1]/[86,64,1]. V2: 149/18/32/[167,64,64,1]/[149,64,1]. Hash is SHA256 of a canonical feature-order definition shared by Node/Python (JSON artifact owned by core task).
- `buildObservation(snapshot, schemaVersion = 1)` and `enumerateLegalActions(snapshot, schemaVersion = 1)` retain V1 behavior; controller selects schema from `weights.schemaVersion`. `weights` envelope V2 carries schemaVersion/observationSchemaVersion/actionSchemaVersion=2, schemaHash, rosterHash, environmentHash, trainingProtocolVersion=2.
- Runtime snapshot keeps existing fields. V2 appends `weaponState` (array of four objects with `present,cooldown,ammoRatio,unlimited,affordability,range,speed,damage`), `activeSlot`, `terrain` (eight normalized ray clearances), `enemyVisible` (or enemy.visible), and `navigation:{dx,dy,stuck,dodging}`, `match:{remaining,ownScore,enemyScore}` (all normalized). Presence masks derive from existing sorted allies/enemies/projectiles. Normalize all new scalars into [0,1], except navigation dx/dy into [-1,1]. Missing values 0, no NaN/Infinity. Terrain rays E,SE,S,SW,W,NW,N,NE over 256px; use existing collision-map clearance and unit radius. Weapon cooldown remaining/fireRate; ammo quantity/maxQuantity or spawn quantity, unlimited separate; affordability minimum clipped current/cost for all positive unit/player costs (no costs => 1); range/map diagonal, speed/1000, known health damage/1000; absent weapon all zeros. Match remaining/duration, ownScore/20 and enemyScore/20 clipped.
- V2 feature order: old86; weaponState slot0..3 each fields in the order above (32); activeSlot onehot4; terrain8; enemy visible3; ally2/enemy3/projectile4 masks (9); navigation dx,dy,stuck,dodging4; match remaining,ownScore,enemyScore3. Targets/enemies use identical deterministic distance/id order. Fire boolean is feature index17 appended to old17. No-fire has slot null and calls stopUsingItem; selected fire must never substitute another slot.
- Controller records canonical observation/options/chosenIndex/logProb/value/simulatedAt/playerId/policyVersion/rosterHash and V2 metadata. Root runtime supplies matchId/lifeId/teamId/potential and execution telemetry. Preserve chosenIndex/logProb of requested action (execution overrides belong to environment, not relabelled PPO samples). V2 avoids triplicate legacy aliases in new output; V1 reader remains compatible.
- TrainingTrajectory.finish retains V1 behavior. V2 sorts by matchId/playerId/time, computes duration-aware transition rewards and terminal outcome only. Required row fields: matchId, lifeId, teamId, potential, schemaVersion, schemaHash, environmentHash, trainingProtocolVersion, requestedAction, executedAction, overrideReasons, nextSimulatedAt. Do not infer terminal at death; dead time discounts until respawn decision. Missing/incompatible data fails rather than silently trains.
- `NeuralTrainer` new options `schemaVersion = 1, environmentHash, trainingProtocolVersion = 2, parentVersion`. V2 uses separate `neural-v2` optimizer folder, while policies retain global n-NNNNNN numbers. Node allocates `--next-version` from max numbered policies+1 and passes Python `--schema-version`, `--environment-hash`, `--protocol-version`, `--parent-checkpoint` on first V2 initialization and `--next-version` on all new writes. Python CLI defaults remain V1 for old tests; V2 requires metadata. Parent checkpoint is old champion optimizer-n-*.pt; V1->V2 migrates common weight columns, zeroes new columns, resets Adam, records parentVersion. V2 resume restores model/Adam/RNG. Never overwrite an existing numbered policy/checkpoint.
- Root runtime propagates metadata from match config/learner weights. Scheduler jobs expose `schemaVersion`, `schemaHash`, `environmentHash`, `trainingProtocolVersion`, `phase` and `opponentVersion`. MatchWorker echoes them into report and config. Mixed V1 opponent with V2 learner is valid; learner trajectories only.
- V2 phases: train, selection, final-test. TrainingRuntime collects gradients only for config.split==='train'; all other splits choose deterministic argmax. Match metadata split uses phase string, not reused old 'validation'. Scheduler old V1 behavior preserved behind schemaVersion=1.
- CLI `--neural-schema 2` selects V2; neural-on default becomes 2. Existing Python/direct Node low-level defaults stay V1. GUI/web neural start explicitly uses 2. New CLI args can flow via existing parseArgs. V2 durable counters/outcomes live in separate neural-state-v2 store; root training status and registry remain shared for GUI. V2 matches persist separately and never resume old trajectories.
- Automatic activation: registry.promote can atomically also update activeVersion when autoUpdate true, retains previous champion. Manual activation remains available. Demo requested selections use string alias `champion` for each automatic team, fixed version string for manual pin. Status includes requested selections and actual resolved versions; aliases refreshed only at round boundary. Both teams default to champion alias for this upgrade. Never start demo with unapproved highest candidate merely because requested='latest'. Desktop approved seed manifest carries champion/previous/active; no trainer in exe.
