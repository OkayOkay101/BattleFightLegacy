# คู่มือผู้เล่น

[English](../en/player-guide.md) · [สารบัญ](index.md)

## เปิดเกมและเลือกโหมด

Standalone สำหรับ Windows เปิดจากไฟล์ portable `.exe` ได้เลย โปรแกรมเปิดเซิร์ฟเวอร์ในเครื่องและหน้าต่างเกมเอง ไม่ต้องติดตั้ง Node, Python หรือเครื่องมือฝึก แยกขั้นตอนเล่น portable ออกจากการรันเว็บจากโค้ด ซึ่งอธิบายใน [คู่มือพัฒนา](development.md)

เลือก **ดูบอทสู้ (Spectate)** เพื่อดู Blue และ Red หรือ **ลงสู้เอง (Play Game)** เพื่อเลือกตัวละครเข้าร่วม Blue สู้กับ Red จากนั้นกด **Enter Game** เวอร์ชัน desktop มีระบบเล่นและเลือก AI แต่ไม่มีการฝึก

## เนื้อหาสร้างเอง

เกมเว็บและ portable ที่ build วันที่ 2026-10-09 มี [ยูนิตและอาวุธสร้างเอง](custom-units.md) พร้อม editor และสนามทดลองผู้เล่น/heuristic แยก การเปลี่ยน catalog อุปกรณ์ด้านล่างเป็น source ที่ใหม่กว่า ดู [บันทึก build](release-notes.md) ก่อนเทียบกับ EXE เดิม

### วิธีใช้

1. เปิด **อาวุธสร้างเอง** สร้างยิงเดี่ยว/กระจาย/เป็นชุด ตั้งดาเมจ ความเร็ว ระยะและคูลดาวน์ แล้วบันทึก
2. เปิด **ยูนิตสร้างเอง** เลือกหนึ่งใน 44 ต้นแบบ ตั้งชื่อ/เลือด/ความเร็ว เลือกอาวุธประจำตัวหรือ custom ที่บันทึก แล้วบันทึกยูนิต
3. เลือกผู้เล่นหรือ heuristic และคู่ต่อสู้ต้นฉบับ กด **ทดลอง** เพื่อเปิดสนาม 1v1 ในเครื่องแยก **เริ่มใหม่** เริ่มแมตช์ใหม่ ส่วน **จบการทดลอง** ปิดเซิร์ฟเวอร์สนาม

Source ไม่เสนอ Stardust Storm/Debris Strike เป็นตัวเลือกเสริมข้ามตัวละครแล้ว PewPew ยังคงอาวุธประจำตัวทั้งสอง และชุดเดิมที่บันทึกยังรองรับ การแทนสกิลเดิมด้วยอาวุธ custom อาจทำให้ร่าง/ทรัพยากร/ซัมม่อนที่พึ่งสกิลนั้นใช้ไม่ได้ การแก้ไขมีผลต่อสนามครั้งถัดไป ยูนิต custom ไม่เข้าแมตช์ปกติหรือการฝึก Neural

## การควบคุมและกล้อง

- การเดินเริ่มต้นใช้ WASD หรือปุ่มลูกศร เล็งด้วยเมาส์และใช้อาวุธที่ถือด้วยปุ่มเมาส์หลัก ปุ่มและเงื่อนไขสกิลกำหนดในข้อมูลแต่ละตัว จึงไม่ควรสมมติว่าทุกตัวใช้เหมือนกัน
- **ติดตามผู้เล่น** ติดตามเป้าหมายที่เลือก **อัตโนมัติ** เลือกเป้าหมายที่มีอยู่ และ **ตัวถัดไป** เปลี่ยนเป้าหมาย เลือกทีม/ผู้เล่นเพื่อดู Blue หรือ Red ได้
- **ดูทั้งแมป** แสดงสนาม ส่วน **กล้องอิสระ** ลากเมาส์ปุ่มขวาเพื่อเลื่อนและใช้ล้อเมาส์ซูม เมื่อต้องการกลับมาติดตามให้เลือก Follow กล้องมีทั้งในโหมดเล่นและผู้ชม
- เมื่อตัวละครตาย ยูนิตอาจหายไประหว่างรอเกิดใหม่ ระบบอัตโนมัติเลือกตัวที่ยังมีชีวิตได้ แต่เป้าหมายที่เลือกเจาะจงอาจไม่มีให้ติดตามชั่วคราว
- เปลี่ยนภาษา English/ไทยผ่านตัวเลือกภาษา ส่วน Error Handling and Compatibility ใช้ภาษาอังกฤษเป็นค่าเริ่มต้นที่กำหนดไว้

## การเลือก AI

เลือกโมเดล Blue และ Red แยกกันได้ `champion` หมายถึงโมเดลที่ผ่านเกณฑ์อนุมัติ ส่วนชื่อหมายเลข เช่น `n-000052` เป็นการตรึงรุ่น ไม่ได้หมายความว่าเป็น champion UI แสดงโมเดลที่ขอและโมเดล/schema ที่ใช้งานจริง การอัปเดต champion alias เกิดเมื่อเปลี่ยนรอบ ไม่เปลี่ยนกลางแมตช์

## Kill feed และสถิติ

Kill feed แสดงการตายล่าสุดและผู้ที่ได้รับเครดิต คะแนนกับสถิติแสดงตามบริบท demo/session ปัจจุบัน ส่วน win rate การประเมินโมเดลฝึกเป็นคนละชุดข้อมูล

| สถิติ | ความหมาย |
|---|---|
| Kill / Death / Assist | ฆ่าศัตรูที่ได้เครดิต การตายที่บันทึก และผู้ร่วมทำดาเมจล่าสุด |
| KDA ใน demo UI | `(kills + assists) / max(1, deaths)`; ถ้า deaths เป็นศูนย์ ตัวหารเป็น 1 |
| Win rate ใน demo UI | `(wins + 0.5 × draws) / เกมที่จบ`; UI ให้เกมเสมอครึ่งแต้ม |
| ดาเมจทำ / รับ | ดาเมจต่อ HP ที่บันทึก ไม่ใช่ DPS หรือความแม่นยำกระสุน |
| การปรากฏของตัวละคร | เกม/ช่วงชีวิตที่ใช้ตัวนั้น เกมหนึ่งมีหลายตัวได้จากการเกิดใหม่ |

Win rate รายตัวใน [รายงานย้อนหลัง](../reports/neural-characters-n27-plus.md) คือทีมชนะในเกมที่ตัวนั้นเคยปรากฏ ไม่ใช่การทดลองใช้ตัวนั้นตลอดเกมโดยแยกปัจจัยอื่น

Exports/รายงานย้อนหลังอาจจัดการ deaths เป็นศูนย์ต่างกัน และใช้ raw win rate (`wins / games`) แทน score ที่ให้เสมอครึ่งแต้มของ demo UI ให้ดูสูตรในรายงานแทนถือว่าทุกหน้าคำนวณเหมือนกัน

## ออฟไลน์และการแก้ปัญหา

Standalone ฝังภาพและ browser dependencies ในเครื่อง บล็อก renderer ขอข้อมูลภายนอกและนำเสียงออก การเลือกโมเดลเก็บใน user-data ของ desktop เมื่อปิดหน้าต่างเกมจะปิดเซิร์ฟเวอร์ที่โปรแกรมสร้างไว้

ถ้าโมเดลหรือ sprite โหลดไม่ได้ ให้เก็บ startup log และชื่อโมเดลที่เลือก ไฟล์ `desktop-startup.log` อยู่ใน user-data ของ Electron สำหรับ BattleFight โดยปกติคือ `%APPDATA%\BattleFight` อย่าเพิ่งลบตัวเลือกหรือ policies ก่อนบันทึกอาการ EXE ที่ไม่ได้เซ็นอาจมีข้อความจาก Windows; รายงาน release ระบุไฟล์และ hash สำหรับตรวจเทียบ
